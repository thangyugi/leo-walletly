TOÀN BỘ CẤU TRÚC: MODULE QUẢN LÝ DANH MỤC

Đặc tả toàn diện từng chi tiết nhỏ nhất trong Module Quản lý danh mục (Category / Group V3). Từ đường dẫn file, cấu trúc cơ sở dữ liệu, các biến lưu trữ cục bộ, luồng validate, đến cách hoạt động của từng nút bấm và tab hiển thị.

1. Bản đồ File & Phân chia Route

Tính năng Quản lý danh mục được xây dựng trên Next.js App Router và chia nhỏ thành các file component, store quản lý trạng thái, và trang chức năng:

Đường dẫn file (Workspace) Loại thành phần Mô tả chức năng
app/categories/page.tsx Route chính (Page) Điểm truy cập trang Quản lý danh mục. Khởi tạo và render component GroupsBentoPage.
features/groups/groups-bento-page.tsx Giao diện chính (Container) Giao diện Bento Grid chứa KPI Strip, thanh điều hướng bộ lọc, lưới Bento Grid các danh mục, widget Phân loại thông minh Leo, và form modal.
app/categories/[id]/page.tsx Route động (Detail Route) Điểm truy cập trang chi tiết của một danh mục cụ thể. Trích xuất id và render component GroupDetailView.
features/groups/group-detail-view.tsx Giao diện chi tiết (Container) Chứa HeroCover, Month Selector, thanh Tab phụ (7 tab) và các panel thống kê chi tiết của một danh mục.
features/groups/group-form.tsx Form nhập liệu (Component) Component Form dùng chung cho cả hành động Tạo mới và Chỉnh sửa danh mục. Quản lý trạng thái nhập liệu, validate độ sâu, và ràng buộc ngân sách.
app/categories/classify/page.tsx Route phụ (Classify Route) Trang tập trung xử lý phân loại hàng loạt các giao dịch chưa được gán danh mục. Render component ClassifyPage.
features/groups/classify-page.tsx Giao diện phân loại (Container) Hiển thị danh sách các giao dịch chưa phân loại kèm dropdown chọn nhanh danh mục phả hệ cho từng giao dịch.
features/groups/store.ts Quản lý trạng thái (Zustand Store) Định nghĩa useGroupStore quản lý danh sách danh mục (groups), loading state và các hàm bất đồng bộ tương tác với Supabase API (fetch, create, update, delete, seed).
stores/transactions.ts Quản lý trạng thái (Zustand Store) Định nghĩa useTransactionsStore quản lý mảng giao dịch toàn cục (transactions) và hàm bulkUpdateTransactions dùng cho tính năng tự động phân loại.

2. Cấu trúc Database & Khai báo Kiểu dữ liệu

Hệ thống sử dụng cơ sở dữ liệu Supabase PostgreSQL với hai bảng cốt lõi là categories, transactions và một database view là category_balances.

Tên cột DB Kiểu dữ liệu Ràng buộc Mô tả nghiệp vụ
id uuid Primary Key Mã UUID phiên bản 4 định danh danh mục.
workspace_id uuid Foreign Key (ledgers) Liên kết đến Workspace chủ quản của sổ cái.
parent_id uuid Foreign Key (categories), Null Mã của danh mục cha. Bằng null nếu là nhóm gốc (Level 1).
name_en, name_vi, name_ja text Not Null Tên danh mục tương ứng theo các ngôn ngữ (EN, VI, JA).
category_type text / enum Default 'cost_center' Loại nhóm: cost_center, department, project, team, subsidiary.
color text Hex Color String Mã màu hex dùng để hiển thị chủ đề của card danh mục.
emoji text Icon Name / Unicode Mã Icon hoặc emoji của nhóm.
path text Không trùng lặp Chuỗi đường dẫn phân cấp (VD: /A001/AA01).
category_code text Tối đa 4 ký tự Mã định danh viết tắt kế toán của danh mục (VD: A001).
sort_order integer Bắt đầu từ 0 Thứ tự sắp xếp thủ công của danh mục so với các nhóm cùng cấp.
is_active boolean Default true true: đang hoạt động, false: đã lưu trữ.
metadata jsonb Default '{}' Lưu trữ: budget_limit (ngân sách tháng), keywords (mảng từ khóa phân loại), is_shared (chia sẻ), is_recurring (định kỳ), rules (mảng các rule nâng cao). 
export interface Group {
  id: string
  workspace_id: string
  parent_id: string | null
  name: string
  name_en: string
  name_vi: string
  name_ja: string
  type: 'cost_center' | 'department' | 'project' | 'team' | 'subsidiary'
  color: string
  emoji: string
  path: string
  categoryCode: string
  sort_order: number
  is_active: boolean
  budget_limit: number
  keywords: string[]
  metadata?: {
    is_shared?: boolean
    is_recurring?: boolean
    rules?: any[]
    [key: string]: any
  }
}

3. Bóc tách Chi tiết dải Chỉ số Tổng quát (KPI Strip)

Giao diện có 4 khối thông tin chỉ số hiển thị dạng dải thanh KPI ngang. Dưới đây là cách tính toán và tương tác cụ thể của từng con số:

A. Chi tiêu tháng này totalExpense
Cách hiển thị lớn
Số tiền chi tiêu tháng hiện tại kèm ký hiệu tiền tệ (Ví dụ: 6,828¥).
Cách hiển thị nhỏ
Số lượng giao dịch phát sinh chi tiêu trong tháng (Ví dụ: 12 giao dịch).
Bảng & Cột dữ liệu
Bảng transactions, các cột: amount, transaction_type, transaction_date.
Hàm & Logic xử lý
- Lấy năm tháng hiện tại dạng chuỗi: ym = "YYYY-MM".
- Lọc giao dịch tháng này: monthTxns = transactions.filter(t => t.transactionDate.startsWith(ym)).
- Tính tổng chi tiêu: totalExpense = monthTxns.filter(t => t.transactionType === 'expense').reduce((sum, t) => sum + Math.abs(t.amount), 0).
- Đếm số giao dịch: monthTxns.filter(t => t.transactionType === 'expense').length.
B. Danh mục hoạt động activeGroupsCount
Cách hiển thị lớn
Số lượng danh mục đang hoạt động (Ví dụ: 18 danh mục).
Cách hiển thị nhỏ
Hiển thị nhãn tĩnh: Đang hoạt động.
Bảng & Cột dữ liệu
Bảng categories, cột is_active.
Hàm & Logic xử lý
- Tính số nhóm đang hoạt động từ store local: activeCount = groups.filter(g => g.is_active).length.
- Thay đổi ra sao: Khi người dùng thêm danh mục mới thành công hoặc chỉnh sửa lưu trữ danh mục, mảng groups trong useGroupStore thay đổi làm kích hoạt render lại số lượng này ngay lập tức.
C. Ngân sách còn lại remainingBudget
Cách hiển thị lớn
Số tiền ngân sách còn lại sau chi tiêu (Ví dụ: 482,172¥).
Cách hiển thị nhỏ
Tỷ lệ phần trăm ngân sách còn lại (Ví dụ: 99% ngân sách còn lại).
Bảng & Cột dữ liệu
Bảng categories (cột budget_limit) và bảng transactions (cột amount).
Hàm & Logic xử lý
- Tính tổng ngân sách: totalBudget = groups.filter(g => g.is_active).reduce((sum, g) => sum + (g.budget_limit || 0), 0).
- Tính ngân sách còn lại: remaining = Math.max(0, totalBudget - totalExpense).
- Tính tỷ lệ phần trăm: pct = totalBudget > 0 ? Math.round((remaining / totalBudget) * 100) : 0.
- Fallback: Nếu totalBudget = 0, phần nhỏ hiển thị: "Chưa đặt ngân sách".
- Màu sắc: Nếu totalExpense > totalBudget, phần trăm hiển thị 0% và nhãn màu chữ chuyển sang màu đỏ báo hiệu vượt ngân sách.
D. Tự động phân loại & Chờ đối soát autoClassify & reconcile
Cách hiển thị lớn
Tỷ lệ tự động phân loại (Ví dụ: 99%) hoặc số lượng chờ đối soát (Ví dụ: 2 giao dịch).
Cách hiển thị nhỏ
Số giao dịch khớp danh mục (Ví dụ: 182 / 184 giao dịch) hoặc nhãn trạng thái đối soát (Ví dụ: Cần xem lại).
Bảng & Cột dữ liệu
Bảng transactions, các cột: category_id, is_reconciled.
Hàm & Logic xử lý
- Tỷ lệ phân loại: (transactions.filter(t => t.categoryId).length / transactions.length) * 100.
- Số giao dịch cần đối soát: transactions.filter(t => !t.isReconciled).length. Nếu số này > 0, hiển thị nhãn màu vàng cảnh báo "Cần xem lại", ngược lại hiển thị "Đã đối soát hết".

4. Bóc tách Thanh điều hướng Bộ lọc & Sắp xếp

Bao gồm bộ chọn lọc loại hiển thị, tìm kiếm thời gian thực và các dropdown điều khiển danh sách:

A. Thanh tab hiển thị (Segmented Tabs) activeTab
Trạng thái phát triển
Đã hoàn thành
Cách thức hoạt động
Khi click vào một tab, state activeTab được thay đổi tương ứng. Giao diện lọc trực tiếp mảng groups trên client-side:
- Tất cả (All): Hiện danh sách các nhóm có is_active === true.
- Đang hoạt động (Active): Hiện danh sách các nhóm có is_active === true. (Hiện tại xử lý tương tự tab Tất cả).
- Chia sẻ (Shared): Lọc danh sách nhóm có metadata.is_shared === true.
- Định kỳ (Recurring): Lọc danh sách nhóm có metadata.is_recurring === true hoặc loại nhóm category_type = 'project'.
- Lưu trữ (Archived): Lọc các nhóm bị vô hiệu hóa có is_active === false.
- Badge đếm số bên cạnh tab: Được tính toán thời gian thực thông qua bộ đếm local React useMemo từ mảng groups ban đầu.
B. Tìm kiếm danh mục (Search Input) search
Trạng thái phát triển
Đã hoàn thành
Cách thức hoạt động
Người dùng nhập từ khóa vào ô tìm kiếm. Trạng thái search lưu trữ chuỗi văn bản. Logic lọc client thực thi tìm kiếm không phân biệt chữ hoa chữ thường (case-insensitive):
- Khớp tên nhóm: name_en, name_vi, name_ja.
- Khớp loại nhóm: category_type (cost_center, project...).
- Khớp từ khóa tự động phân loại: tìm kiếm trong mảng keywords của danh mục.
- Không thực hiện gọi API database khi gõ phím để giữ hiệu năng mượt mà.
C. Dropdown "Tài khoản: tất cả" Dropdown
Trạng thái phát triển
Chưa phát triển (Chỉ hiển thị giao diện tĩnh/UI Placeholder).
Logic thiết kế sau này
Dropdown sẽ truy vấn danh sách tài khoản từ bảng payment_instruments và lọc danh sách danh mục chỉ hiển thị những nhóm có giao dịch liên kết với tài khoản được chọn.
D. Dropdown "Sắp xếp: chi tiêu cao nhất" Dropdown
Trạng thái phát triển
Chưa phát triển (Chỉ hiển thị giao diện tĩnh/UI Placeholder).
Cách hoạt động hiện tại
Hệ thống đang tự động sắp xếp mặc định theo chi tiêu từ cao đến thấp bằng cách lấy dữ liệu chi tiêu trong tháng hiện tại từ mảng giao dịch. Khi click dropdown này chưa làm thay đổi logic sắp xếp.
E. Toggle "Bento" ViewToggle
Trạng thái phát triển
Chưa phát triển (Mặc định luôn khóa hiển thị dạng lưới bento grid phẳng 4 cột, chưa hỗ trợ đổi sang List View).

5. Cấu trúc các thẻ bên trong Lưới Bento Grid

Lưới Bento Grid hiển thị hỗn hợp các thẻ KPI, Thống kê, và Thẻ thông tin danh mục:

Các loại thẻ đặc biệt trong Grid

  • Featured Card (Danh mục nổi bật): Thẻ chiếm diện tích lớn gấp đôi, tự động hiển thị danh mục có chi tiêu lớn nhất trong tháng hiện tại, kèm biểu đồ ngân sách phóng to.
  • Auto Classify Card (Thống kê phân loại): Thẻ màu sẫm hiển thị số lượng giao dịch đã được hệ thống tự động phân loại, tỷ lệ % và gợi ý đặt thêm từ khóa.
  • Top Spending Groups Card (Nhóm chi nhiều nhất): Liệt kê danh sách top 3 nhóm chi tiêu nhiều nhất kèm thanh tiến trình nhỏ.
  • Add Group Tile (Ô Tạo danh mục mới): Một thẻ trống có viền nét đứt và nút cộng ở cuối danh sách bento, bấm vào sẽ kích hoạt mở Modal Tạo nhóm mới tương tự như nút bấm ở header.
  • Archive Strip (Thanh Lưu trữ): Nằm ở dưới cùng của lưới Bento Grid, chỉ xuất hiện nếu có nhóm lưu trữ, click vào để xem các nhóm đã bị ẩn (is_active = false).

Thẻ danh mục thông thường (Regular Group Card)

Cấu trúc chi tiết của một thẻ Danh mục
1. Biểu tượng & Màu sắc
Hiển thị Emoji (emoji) đặt trên nền màu nhạt của mã màu chủ đề (color + "22").
2. Tên nhóm
Tên của danh mục (name). Khi rê chuột vào thẻ sẽ hiển thị hiệu ứng đổi màu tên nhóm.
3. Số nhóm con & Giao dịch
Bong bóng số nhỏ ở góc hiển thị số lượng danh mục con trực thuộc tầng dưới và số lượng giao dịch phát sinh trong tháng của nhóm đó.
4. Chi tiêu tháng này
Số tiền chi tiêu thực tế của nhóm tính bằng tổng các giao dịch thuộc danh mục này trong tháng.
5. Thanh Tiến độ Ngân sách
Thanh progress bar hiển thị tỷ lệ chi tiêu thực tế so với ngân sách hạn mức (budget_limit). Nếu chi tiêu vượt quá 90% ngân sách, thanh tiến độ sẽ tự động chuyển sang màu cam/đỏ cảnh báo.
6. Ngân sách còn lại
Hiển thị số tiền ngân sách còn lại. Nếu nhóm chưa cấu hình ngân sách (budget_limit = 0), hiển thị ký hiệu —.

6. Luồng Nghiệp vụ Tạo/Sửa & Đặc tả GroupForm

Hành động Tạo mới hoặc Chỉnh sửa danh mục đều gọi component GroupForm hiển thị trong Modal. Component này thực thi các logic validate ràng buộc cấu trúc cây dữ liệu phức tạp.

Các Trường Nhập Liệu Trong Form
Tên nhãn Form Kiểu nhập liệu State React tương ứng Validate & Logic Xử Lý
Tên nhóm Text Input formData.name Bắt buộc (required). Nhập tên đại diện cho nhóm.
Loại nhóm Select Dropdown formData.type Giá trị thuộc kiểu GroupType (cost_center, department, project, team, subsidiary). Mặc định là cost_center.
Nhóm cha (nếu có) Select Dropdown formData.parent_id Danh sách lựa chọn được tính toán bằng parentOptions:
- Không hiển thị chính danh mục đó (khi chỉnh sửa) để tránh tự chọn mình làm cha.
- Loại bỏ tất cả các danh mục thuộc nhánh con của danh mục hiện tại để tránh vòng lặp đệ quy vô hạn.
- Kiểm tra độ sâu: Chỉ hiển thị các nhóm cha thỏa mãn công thức: (Độ sâu của cha + Chiều cao nhánh con hiện tại) ≤ 4 để bảo vệ giới hạn tối đa 4 tầng của hệ thống.
Biểu tượng (Icon) Lưới chọn Icon (8 biểu tượng preset) formData.emoji Biểu tượng được tô màu chủ đề được chọn bên dưới để đồng bộ nhận diện thương hiệu trực quan.
Màu sắc Lưới chọn màu sắc (8 màu preset dạng tròn) formData.color Mặc định chọn màu đầu tiên của mảng preset màu sắc.
Ngân sách hàng tháng Number Input formData.budget_limit Giá trị số. Mặc định bằng 0 (không giới hạn chi tiêu).
Từ khóa phân loại Input Text + Nút "Thêm" formData.keywords Người dùng nhập từ khóa và nhấn Enter hoặc nút "Thêm":
- Đẩy chuỗi từ khóa vào mảng keywords.
- Hiển thị các tag từ khóa dạng pill kèm nút X màu đỏ để xóa từ khóa khỏi danh sách.
- Nếu người dùng nhập dở từ khóa trong ô input mà bấm "Lưu nhóm" ngay, hệ thống tự động nhận diện và đẩy từ khóa dở này vào mảng trước khi gửi payload lên API.
Quy tắc Validate Ngân sách của Form
Điều kiện kích hoạt
Nhóm đang tạo/sửa có chọn parent_id (tức là nhóm con) và có khai báo hạn mức budget_limit > 0. Nhóm cha cũng phải có cấu hình budget_limit > 0.
Công thức kiểm tra
Hệ thống lấy danh sách các nhóm con khác đang cùng trực thuộc nhóm cha đó (loại trừ nhóm hiện tại nếu đang chỉnh sửa), cộng dồn ngân sách của chúng và cộng thêm ngân sách đề xuất của nhóm hiện tại:
Tổng ngân sách con = (Ngân sách nhóm mới/sửa) + (Tổng ngân sách các nhóm con cùng cha khác)
Nếu Tổng ngân sách con > Ngân sách của nhóm cha, hệ thống kích hoạt hiển thị Budget Warning Modal.
Hành động Cảnh báo
- Người dùng click "Xem lại": Đóng hộp thoại cảnh báo, giữ lại form để chỉnh sửa thông số.
- Người dùng click "Vẫn tiếp tục lưu": Tiếp tục gọi API lưu đè dữ liệu bất chấp vượt hạn mức.

7. Chi tiết các thành phần trang Dynamic Route /categories/[id]

Khi nhấp vào card danh mục, hệ thống điều hướng đến trang chi tiết. Tại đây hiển thị 7 tab thông tin phục vụ quản lý sâu:

A. Header Cover & Month Selector Đã hoàn thành
Header Cover
Hiển thị dải màu gradient từ màu chủ đề của nhóm, tên nhóm kèm emoji, số thành viên, và các nút chỉnh sửa (Pencil) và xóa (Trash) danh mục.
Month Selector
Ô chọn tháng dạng input type="month" cho phép thay đổi phạm vi hiển thị dữ liệu của toàn bộ các tab bên dưới theo tháng được chọn.
Bóc tách 7 Tab Nội dung phụ bên trong
Tên Tab Thành phần giao diện hiển thị Logic xử lý & Tương tác API
Tổng quan (Overview) - Thống kê chi tiết: Tổng chi tiêu, Hạn mức ngân sách, Trung bình chi tiêu mỗi người, và số lượng giao dịch đã khớp từ khóa tự động.
- Tiến trình sử dụng ngân sách. 		Tính toán động dựa trên mảng giao dịch của tháng được chọn.
Nhóm con (Subgroups) - Lưới các danh mục con trực thuộc.
- Nút chuyển đổi sắp xếp: "Theo chi tiêu" hoặc "Theo tên".
- Nút "Thêm nhóm con": Tự động mở modal điền sẵn parent_id. Nút này sẽ chuyển thành nhãn Đạt cấp tối đa (Cấp 4) nếu cấp độ sâu của nhóm hiện tại bằng 4. 		Lọc các danh mục trong store có parent_id = groupId. Sắp xếp mảng trực tiếp ở client khi chuyển đổi tab sắp xếp.
Từ khóa (Keywords) - Quản lý từ khóa tự động phân loại của nhóm và các nhóm con trực thuộc.
- Thống kê số lần khớp (hits) từ khóa trong lịch sử giao dịch.
- Thêm/Xóa từ khóa thời gian thực.
- Quản lý Quy tắc đang hoạt động (Advanced Rules) lưu tại trường metadata.rules, cho phép bật/tắt bằng Toggle switch. 		- Thống kê hits: Quét mảng giao dịch local để tìm chuỗi chứa từ khóa.
- Thêm/Xóa từ khóa: Gọi API cập nhật mảng keywords của danh mục tương ứng tại database.
Giao dịch (Transactions) - Danh sách các giao dịch thuộc danh mục này.
- Thanh tab phân loại con: Tất cả, Tự động (khớp từ khóa), và Cần xem lại (chưa đối soát).
- Nút "Xem tất cả" để dẫn sang trang Lịch sử giao dịch tổng hợp. 		Lọc giao dịch theo categoryId === currentGroupId của tháng được chọn.
Số dư (Balances) Hiển thị số tiền dư nợ thực tế của từng thành viên trong nhóm chi tiêu chung. Lấy dữ liệu từ view category_balances và thực hiện phép chia đều cho số lượng thành viên.
Thành viên (Members) Danh sách ảnh đại diện (avatar) tròn của các thành viên sở hữu sổ cái đang dùng chung nhóm chi tiêu này. Truy vấn từ bảng ledger_members và thông tin cấu hình vai trò của tài khoản.
Cài đặt (Settings) Nơi cho phép lưu trữ nhóm (vô hiệu hóa tạm thời) hoặc xóa vĩnh viễn danh mục khỏi hệ thống. - Lưu trữ: Update is_active = false.
- Xóa: Gọi lệnh DELETE danh mục. Kích hoạt xóa Cascade các con ở DB.

8. Leo Phân loại thông minh & Trang Classify Page

Tính năng phân loại giao dịch tự động giúp người dùng dọn dẹp các giao dịch "chưa được phân loại" một cách thông minh.

A. Trang Classify Page tập trung (Route: /categories/classify) Đã hoàn thành
Input tìm kiếm
Lọc nhanh các giao dịch theo chuỗi văn bản gõ vào (khớp tên cửa hàng hoặc mô tả giao dịch). Xử lý lọc reactive tại client-side.
Danh sách giao dịch
Hiển thị các giao dịch có categoryId rỗng và loại giao dịch khác chuyển khoản (transactionType !== 'transfer'). Hiển thị ngày tháng, nguồn tiền liên kết (Ví dụ: MoMo, VCB), số tiền chi tiêu.
Dropdown chọn nhanh
Mỗi giao dịch hiển thị một select dropdown chứa toàn bộ cây danh mục phả hệ hoạt động của Workspace. Nếu giao dịch khớp từ khóa tự động, danh mục gợi ý sẽ được chọn sẵn làm mặc định giúp tiết kiệm thời gian.
Nút "Lưu phân loại"
Gọi hàm API cập nhật hàng loạt bulkUpdateTransactions gửi payload chứa danh sách các giao dịch được gán danh mục lên Supabase. Kết thúc sẽ chuyển hướng người dùng quay lại trang quản lý danh mục.
