2. Màn hình chính /categories

Component: features/groups/groups-bento-page.tsx. Khi load, gọi 2 hàm song song:

  • fetchGroups(ledgerId) → query categories và category_balances
  • syncTransactions(500) → query transactions giới hạn 500 bản ghi

Nếu isLoading = true → hiện spinner toàn trang. Nếu groups.length === 0 → hiện trạng thái trống với một ô "Tạo danh mục mới".

ElementLoạiChức năng

2.2 KPI Strip (4 ô thống kê)

Loại: Tĩnh – chỉ hiển thị, không có tương tác. Tất cả số liệu tính toán client-side từ dữ liệu đã fetch.

Ô KPITính từ đâu
Chi tiêu tháng này Lọc transactions theo transactionDate.startsWith(YYYY-MM) tháng hiện tại + transactionType === 'expense' → sum Math.abs(amount)
Ngân sách còn lại sum(groups.budget_limit) – chi tiêu tháng. budget_limit lấy từ metadata.budget_limit trong bảng categories.
Tự động phân loại (%) transactions.filter(t => t.categoryId).length / transactions.length * 100. Tính trên toàn bộ transactions đã load, không giới hạn tháng.
Chờ đối soát transactions.filter(t => !t.isReconciled).length. Trường is_reconciled từ bảng transactions.

6.7 Đánh giá và đề xuất

🔴 Lỗi nghiêm trọng: Không filter ledger_id khi fetch transactions
Query SELECT * FROM transactions ORDER BY transaction_date DESC LIMIT 500 lấy toàn bộ transactions của hệ thống, không lọc theo ledger. Nếu người dùng có nhiều sổ cái hoặc là multi-tenant, dữ liệu từ sổ cái khác sẽ lẫn vào. Cần thêm .eq('ledger_id', currentLedger.id).
🔴 Dữ liệu đa ngôn ngữ ghi trùng 3 cột
Khi tạo/sửa nhóm, code ghi cùng một giá trị vào name_en, name_vi, name_ja. Tính năng đa ngôn ngữ thực sự chưa hoạt động – UI không cho nhập tên riêng theo ngôn ngữ.
🟡 budget_limit và keywords lưu trong JSONB metadata thay vì cột riêng
Cả hai trường quan trọng này nằm trong categories.metadata (JSONB) thay vì cột riêng. Điều này khiến việc query, index, và validate trở nên phức tạp. Code phải fallback nhiều lần: metadata.budget_limit || budget_limit. Nên tách thành cột budget_limit NUMERIC và keywords TEXT[].
🟡 View category_balances có thể không tồn tại
Code có try/catch fallback sang group_balances rồi fallback về mảng rỗng. Không có thông báo lỗi cho người dùng. Nếu cả hai view không tồn tại, tab "Số dư" sẽ luôn hiển thị 0.
🟡 Rules trong KeywordManager không được lưu DB
Toggle on/off quy tắc và "Thêm quy tắc" chỉ cập nhật React state local. Khi reload trang, tất cả thay đổi mất. Cần gọi updateGroup(id, {metadata: {rules}}).
💡 Đề xuất: Thêm cột vào bảng categories
Nên tách budget_limit NUMERIC(20,6) và keywords TEXT[] ra khỏi JSONB. Thêm index GIN(keywords) để keyword search hiệu quả hơn. Thêm cột ledger_id UUID để có thể query categories theo sổ cái nếu cần.
💡 Đề xuất: Bảng transactions
Xác nhận rõ ràng đang dùng bảng nào: transactions hay transactions_v3 (cả hai đều được đề cập trong codebase). Thêm filter .eq('ledger_id', ledgerId) vào câu query fetch. Cân nhắc tăng limit từ 500 lên hoặc dùng pagination để đảm bảo đủ dữ liệu cho tính toán KPI.
💡 Đề xuất: Tạo view category_balances chính thức
Hiện view này không đảm bảo tồn tại. Nên tạo migration để tạo view hoặc materialized view tính toán balance từ transactions theo category, đảm bảo luôn có dữ liệu cho tab Số dư.

1.4 View category_balances (mới hoàn toàn)

CREATE OR REPLACE VIEW category_balances AS
SELECT
  c.id                                                     AS group_id,
  c.name_en                                                AS name,
  t.ledger_id,
  date_trunc('month', t.transaction_date::TIMESTAMPTZ)     AS month,
  SUM(CASE WHEN t.transaction_type = 'income'  THEN t.amount ELSE 0 END)  AS total_income,
  SUM(CASE WHEN t.transaction_type = 'expense' THEN t.amount ELSE 0 END)  AS total_expense,
  SUM(CASE WHEN t.transaction_type = 'income'  THEN  t.amount
           WHEN t.transaction_type = 'expense' THEN -t.amount ELSE 0 END) AS net_balance,
  COUNT(t.id)                                              AS transaction_count
FROM categories c
JOIN transactions t ON t.category_id = c.id
WHERE t.deleted_at IS NULL
GROUP BY c.id, c.name_en, t.ledger_id,
         date_trunc('month', t.transaction_date::TIMESTAMPTZ);

View này thay thế tính toán inline trong store, đảm bảo luôn tồn tại và dùng được khi tab Số dư được mở.
